# 審査メモの雛形(提出時に「アプリ審査情報」のメモ欄へ入れる内容)

**これは提出に含める情報であり、Apple への「返信」ではない。** 提出前チェック(段階3)に通過してから作る。
審査員が追加情報(2.1 Information Needed)を求めずに審査を進められるよう、最初から全項目を含める。
個人情報は書かない(姓名・メール・電話は、App Store Connect の各欄に本人が手入力する)。

## 含める項目(全て)
1. **実機の画面録画**
   - 最新の OS を搭載した実機で撮る(シミュレータは不可)。
   - アプリを完全に終了した状態から録画を始め、起動 → 一般的なユーザーフロー(主要な画面を一通り)を映す。
   - 次がある場合は、必ず映す: アカウント登録・ログイン・アカウント削除、ユーザー生成コンテンツ(報告・ブロックの仕組みを含む)、有料コンテンツ・機能へのアクセス。
   - ない場合は、「ない」とメモに書く。
   - 通知や個人情報が映らないようにする。提出方法(添付 / 限定公開の閲覧URL)は、App Store Connect の画面で確認する。
2. **目的と対象ユーザー**: 解決する問題と提供する価値(宣伝文ではなく実際の説明)。
3. **主要機能へのアクセス方法**: 手順。ログインの要否、必要な認証情報、サンプルファイルの要否。
4. **外部サービス・ツール・プラットフォームの一覧**: データ提供元、認証、決済、広告、AI サービスなど。ない項目は「使用していない」と書く。
5. **地域差**: 地域で機能・内容が違うか。違わなければ「全地域で同じ」と書く(広告の同意フォームが出る地域があれば、それも書く)。
6. **規制業界・保護された第三者の素材**: 該当するか。該当する場合は、権限を示す資料。(年齢制限が必要な内容、第三者の素材、音声・画像・フォントのライセンスなど)

## 注意
- 録画の内容と、スクリーンショット、ストア説明、メモの記述は、全て一致させる(未実装の機能を書かない)。
- 録画は、提出するビルドと同じビルドで撮る。
- メモ欄が埋まっていても、提出したビルドが実機で動かなければ、別の理由(2.1 バグ・クラッシュ)で止まる。実機テストを先に終える。
- スクリーンショットは、タイトル画面・ログイン画面・スプラッシュだけでなく、実際に使っている画面にする(2.3.3)。
