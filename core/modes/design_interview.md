# 画面デザインの参考画像(ChatGPT 用のインタビュー形式の指示文)

画面デザインを確定する時に、AI(Claude)がこの指示文を**既知の情報を埋めた形**で出す。オーナーは ChatGPT に貼り、質問に番号で答えるだけで、参考画像が出来る。
目的: 書く手間を減らし、コードだけでは出せない世界観を、画像で先に固める(実装の前に決める)。

## Claude の作り方(出す前に)
1. 次の情報を、設計書・3つの質問の答え・フォント・色から**埋める**(オーナーに聞き直さない): アプリの一言、想定ユーザー、系統(A/B/C)、Era / Rule / Voice、基本色(16進数)、使うフォント、主な操作、変更不可の点。
2. 埋まらない項目だけ、ChatGPT が質問する形にする。質問は最大5問。
3. 添付するもの(あれば): 設計書、参考画像、アイコン案。
4. 出す時に「添付するもの」と「貼る先: ChatGPT」を一行で添える。

## 指示文(`【】` は Claude が埋めてから渡す)
```
あなたは、小さなiPhoneアプリのUIデザイナー兼インタビュアーです。
私(オーナー)は文章を書くのが面倒です。下の既知の情報を前提に、足りない点だけ質問して、
「アプリのデザイン参考画像」を作ってください。

■ 既知の情報(質問しないでください)
- アプリの一言:【】
- 想定ユーザー:【】
- 系統:【A 紙・学習 / B ゲーム・個性 / C 実用】
- 縛り:Era【】/ Rule【】/ Voice【】
- 基本色:【16進数を3〜4色】
- フォント:日本語【】/ 英語【】
- 主な操作:【】
- 変更不可:【】

■ 質問のルール
- 一度に聞くのは1〜3問。短く聞く(会話の形態が「推奨」なら、番号つきの選択肢で。`modes/conversation_style.md`)。おすすめを1番に置き、理由を一言添える。
- 私は番号か一言で答える。「おまかせ」と言ったら、おすすめで進め、理由を一言添える。
- 質問は全部で5問以内。既知の情報は聞かない。

■ 聞くこと(既知でない項目だけ)
1. 主役のモチーフ(アイコンと画面の中心になる題材)
2. 雰囲気の細かい好み(質感、線の太さ、影の有無)
3. 好きな点・避けたい点(参考画像があれば、その要素)
4. 主要な画面のうち、特に力を入れたい画面
5. 入れたくないもの

■ 質問のあとにやること
1. デザイン方針(色、質感、雰囲気、文字の印象)を3〜5行で示す。
2. 私が OK と言ったら、次の画像を1枚ずつ作る。
   1) ホーム画面  2) 代表的な操作画面  3) 操作に対する画面の変化(成功と失敗など)
   4) 結果・進捗の画面  5) 空の状態 / エラー  6) 設定などその他の画面(任意)  7) 配色とタイポグラフィの見本
3. 修正を頼んだら、全体の統一を保ったまま直す。

■ 画像の共通ルール
- iPhoneの縦長画面(約 9:19.5)。端末の枠や手は描かず、画面だけ。
- 全ての画像で、色、文字、角丸、余白、ボタンの形を統一する。
- 機能とボタンは最小限。意味のない要素は置かない。簡素でも安っぽくしない。
- 説明なしで使える画面。主要な操作は片手で届く位置。
- 文字は日本語で、読める大きさ。誤字を避ける。
- 既存アプリ、ブランド、ロゴ、キャラクターに似せない。
- アイコンの図柄を、画面内の他の場所に使い回さない。

■ 出力について
- 画像と、用途の一言だけを返す。長い説明は不要。

では、最初の質問から始めてください。
```

## 受け取った後
- 画像は `docs/references/` に保存する(ファイル名: `01_home.png` など)。
- 画像は雰囲気の参考。画面構成・素材をそのまま真似せず、実装で独自に作る。実機のプロトタイプで操作感を確認する。
- 画像の枚数・用途・状態を `docs/asset_list.md` に記録する(出典: ChatGPT)。
- 画像と実機は違うので、実装後に `ui_review.md`(ChatGPT)で、画面を再度レビューする。
