# アニメーションの作り方(コマ撮り方式)

アプリ内のアニメーション全般(起動・演出・ローディング・結果表示など)の既定は、**ChatGPT に静止画を1コマずつ生成させ、コードでつなぎ合わせる**方式にする。指示がある時、またはコード描画の方が明らかに良い時(図形の動き、数値の変化など)は、そちらを優先してよい(ルールではない)。

## 手順
1. 場面ごとに、コマ数(目安 4〜8)・1コマの秒数・合計秒数を決める(起動は `modes/launch_animation.md` の上限に従う)。
2. **基準プロンプト**(画風・キャンバスサイズ・背景・構図・色・文字なし)を1つ作り、オーナーに渡す。
3. **差分プロンプト**を1コマずつ作る(「基準と同じ構図・画風で、〇〇だけが変わる」)。1コマ生成するたびに、前のコマの画像を添付して続けるよう案内する。
4. 全コマ同じサイズ・同じ背景・同じ余白にそろえる(ずれるとチラつく)。文字は画像に焼き込まず、コードで描く(固定フォント)。
5. ファイル名は `場面名_01.png`, `場面名_02.png` … とし、`docs/asset_list.md` に出所・生成日・利用条件を記録する(`modes/asset_requests.md`)。
6. 他の場面・アイコン・他アプリのアニメーションは使い回さない。

## つなぎ合わせ(コードで)
- SwiftUI: 画像の配列とコマ番号の状態を、`TimelineView` または `Timer` で更新。
- Android(Compose): コマ番号の状態を、`LaunchedEffect` + `delay` で更新(`workflow/android_guide.md`)。
- Godot: `AnimatedSprite2D` の `SpriteFrames`。
- 実装の細部は、使う時に公式を確認する(ここでは一般知識で、公式での確認はしていない)。

## 必ず守る
- 「動きを減らす」設定(iOS: Reduce Motion / Android: アニメーション倍率 0)の時は、**最後のコマを静止で表示**する。自前のタイマーは、Android では自動では守られないので自分で判定する。
- タップでスキップできる。待たせない(読み込みは裏で並行)。
- 画像サイズ・枚数が重くならないか(メモリ・アプリ容量)確認する。必要なら縮小・減枚する。
- 生成画像の利用条件・著作権・実在の人物やロゴに似ていないかを確認する(`modes/asset_requests.md`)。
