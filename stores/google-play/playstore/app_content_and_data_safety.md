# アプリのコンテンツと宣言(Play Console)

Play Console の「アプリのコンテンツ」で宣言する項目。**実装・公開ページのプライバシーポリシーと必ず一致させる。** 推測で回答しない。質問の全文と選択肢は、Play Console の現在の画面で確認する(画面は変わる)。
個人情報(連絡先メールなど)は本人が手入力。

## 宣言する項目
| 項目 | 内容 | 注意 |
|---|---|---|
| プライバシーポリシー | 公開済みのURL | 子ども向けを含むアプリは、ストア掲載とアプリ内の両方に必要。申請前に公開済みであること |
| 広告 | 広告を含むか(はい/いいえ) | AdMob などを使うなら「はい」。実装と一致させる |
| アプリのアクセス | ログインが必要な部分があるか。ある場合はテスト用の手順・認証情報 | ログイン不要なら、その旨を選ぶ。認証情報の秘密はチャットに出さず、本人が手入力 |
| ターゲット層とコンテンツ | 対象の年齢層 | 子どもを含むと、Families ポリシーの追加要件がかかる。含めるかは、設計(アルコール等)と合わせて慎重に |
| コンテンツレーティング | 質問票(IARC)に回答 | 実際の内容に基づいて回答。過少申告しない |
| データセーフティ | 収集するデータ、共有、目的、暗号化、削除の方法 | 下記 |
| 権限の宣言 | 機密性の高い権限を使う場合のみ | 使わないなら不要。不要な権限は入れない |

## データセーフティ(AI が整理して、本人が入力する)
1. アプリ・SDK(広告、分析、クラッシュ報告など)が**実際に収集・共有するデータ**を、コードから洗い出す(端末ID、広告ID、おおまかな位置、クラッシュログ、使用状況など)。
2. 端末内にだけ保存し、外に送らないデータは、「収集」に当たらない場合がある(Google の定義を公式で確認)。広告 SDK 経由の収集は、ログインがなくても起こり得る。
3. データの種類ごとに、目的、共有の有無、任意か必須か、を整理する。
4. 暗号化(転送中)、削除のリクエスト方法を整理する。
5. プライバシーポリシーの記述と矛盾しないことを確認する。
6. 回答の一覧を `playstore/kit.md` に書く(選択肢のラベルを明記)。入力は本人が行う。

## 広告・同意
- Google Mobile Ads SDK を使う場合、EEA・英国などでは同意の取得(UMP)が必要。Apple 側の ATT とは別の仕組み。
- 広告ユニットIDの使い回し、テスト広告IDの残りに注意(Apple と同じ)。
- 本番の広告を、開発中の自分の端末でタップしない。
