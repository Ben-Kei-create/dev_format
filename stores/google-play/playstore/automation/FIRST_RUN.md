# 最初の実行手順(Mac・Google Play)― サービスアカウントの作成から `plan` まで

**この手順は、`plan`(下書きを作って読み、破棄する)までで終わる。`apply` は、結果をオーナーが確認し、会話で OK してから。`--commit` は、さらに別の承認。**
公式で確認した点には(公式)、確認できていない点には(要確認)と付ける。確認日 2026-11-06。

## 0. 前提
- [ ] **オーナーが実装完了を宣言した**
- [ ] Play Console に**アプリが作成済み**(API では作れない)。パッケージ名が決まっている
- [ ] 個人アカウントの場合、クローズドテストの要件(12 人 × 14 日)の計画がある(`workflow/closed_testing.md`)
- [ ] Mac に Python 3 がある。作業は**オーナーの Mac 上**(クラウドのセッションでは使わない)

## 1. Google Cloud でサービスアカウントを作る
- [ ] Google Cloud のプロジェクトを用意する(無ければ作る)(公式)
- [ ] 「Google Play Developer API」のページで **有効化(Enable)** する(公式)
- [ ] 「サービスアカウント」のページで **サービスアカウントを作成**する(公式)
- [ ] サービスアカウントの **JSON 鍵**を作成してダウンロードする(手順は Google Cloud の公式ドキュメント。Play の入門ページには記載なし)(要確認)
- [ ] 鍵は**リポジトリの外**に置き、`chmod 600`(例: `~/.play/service-account.json`)。**コミットしない・チャットに貼らない・ログに出さない**(公式も「許可のない人に渡さない」と明記)
- [ ] サービスアカウントの**メールアドレス**を控える(次の手順で使う)

## 2. Play Console でサービスアカウントを招待する
- [ ] Play Console → **ユーザーと権限(Users & permissions)→ 新しいユーザーを招待**(公式)
- [ ] サービスアカウントの**メールアドレス**を入力する(公式)
- [ ] 権限は**必要最小限**。このスクリプトは、掲載情報・画像・データセーフティを扱う。必要な権限の名前は、Play Console の権限の説明で確認する(要確認)。公式の入門ページの例にある課金系の権限は、このスクリプトでは不要
- [ ] 「ユーザーを招待」を押す。公式の説明では、これでサービスアカウントから API が使える。使えない場合(401 / 403)は、少し待って再試行する(待ち時間の記載は公式になし)

## 3. 環境を整える
- [ ] `pip install pyjwt cryptography`(仮想環境を使ってよい。`.venv` はコミットしない)
- [ ] 現在の端末だけに環境変数を設定する(ファイルに書かない):
  ```bash
  export PLAY_SA_KEY_PATH="$HOME/.play/service-account.json"
  ```
- [ ] 自己テスト(ネットワークなし): `cd playstore/automation && python3 -m unittest 2>&1 | tail -3` → `OK`

## 4. 入力ファイルを作る
- [ ] AI が `playstore/kit.md` から `play.json` を作る(`play.example.json` が見本)
- [ ] 個人情報が入っていない(入っていると止まる)
- [ ] 文字数: タイトル30、短い説明80、詳しい説明4,000(超えると止まる。公式)
- [ ] 画像: スクリーンショットは端末の種類ごとに最大8枚・アルファなし・各辺320〜3840px・長辺は短辺の2倍まで、アイコンは512×512 PNG(1024KB以下)、フィーチャーグラフィックは1024×500(アルファなし)(公式。`plan` が検査する)
- [ ] データセーフティ: Play Console から現在の CSV テンプレートをダウンロードし、AI が実装に基づいて整理し、**オーナーが内容を確認**する。API は書き込みのみで、**現在の値は読めない(差分なし・宣言全体を上書き)**

## 5. `plan` を実行する
```bash
python3 playstore/automation/play_sync.py plan play.json
```
- [ ] 下書き(edit)を作って現在の掲載情報を読み、**破棄**する。何も確定しない
- [ ] 出力の確認:
  - [ ] 各項目の「現在」と「新規」が、意図どおりの差分
  - [ ] 画像の「既存 N 枚」(置き換えには `--allow-delete-images` が必要)
  - [ ] データセーフティは「宣言全体を上書き」と表示されることを理解した
  - [ ] `!` の警告を読んだ(スクリーンショットは、公開に最低2枚など)
- [ ] 差分をオーナーに見せる(AI は、ここで止まる)

## 6. うまくいかない時
| 症状 | 確認すること |
|---|---|
| トークンの取得に失敗 | JSON 鍵のパスが正しいか。鍵が失効していないか。端末の時刻 |
| HTTP 401 / 403 | Play Console でサービスアカウントを招待したか。権限が足りない。API を有効化したプロジェクトか |
| HTTP 404 | パッケージ名が一致しているか。アプリを Play Console で作成済みか |
| 画像で止まる | 寸法・アルファ・枚数を `plan` の表示で確認 |
| 画像の種類のエラー | 対応は `phoneScreenshots` / `sevenInchScreenshots` / `tenInchScreenshots` / `icon` / `featureGraphic` |

## 7. `plan` の次(別の承認が必要)
- `apply`(`--confirm-package`)は、サーバーで検証して**下書きを破棄**する予行。確定は、さらに別の承認を得てから `--commit`。確定は公開に送る操作(公開済みのアプリでは審査に送られる)。
- データセーフティは `datasafety` コマンドで別に送る(`--confirm-package` が必要)。
- 手順の全体は `README.md`。
