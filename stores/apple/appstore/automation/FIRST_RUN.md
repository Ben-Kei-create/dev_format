# 最初の実行手順(Mac・Apple)― 鍵の作成から `plan` まで

**この手順は、`plan`(読み取りのみ)までで終わる。`apply` は、`plan` の結果をオーナーが確認し、会話で OK してから(別の手順)。**
公式で確認した点には(公式)、確認できていない点には(要確認)と付ける。確認日 2026-11-06。

## 0. 前提(全部そろってから始める)
- [ ] 実装が終わり、**オーナーが実装完了を宣言した**(`CLAUDE.md` のガード)
- [ ] App Store Connect に**アプリのレコード**がある(API では作れない。画面で作成済み)
- [ ] 対象の**バージョンが作成済み**で、編集できる状態(`PREPARE_FOR_SUBMISSION` など)
- [ ] 入力したい**ロケールが追加済み**(`plan` は、無いロケールを作らず通知するだけ)
- [ ] Mac に Python 3 がある(`python3 --version`)
- [ ] 作業は**オーナーの Mac 上**(クラウドのセッションでは使わない)

## 1. API キーを作る(App Store Connect の画面)
- [ ] App Store Connect → **ユーザとアクセス → 統合 → App Store Connect API**(公式)
- [ ] **チームキー**: アカウントホルダーまたは管理者が「チームキー → API キーを生成」。キーの名前は自分用の呼び名(キー自体には含まれない)(公式)
- [ ] **アクセス(ロール)は必要最小限**を選ぶ。チームキーは全アプリに適用され、アプリ単位では絞れない(公式)。メタデータの編集に必要なロールは、Apple の権限の表で確認する(要確認)
- [ ] 作成後は、名前もアクセスも**変更できない**(変えるなら失効して作り直す)(公式)
- [ ] 個人用キー(プロフィールの編集 → 個人 API キー)もある。1人につき有効なキーは1つ(公式)。どちらで足りるかは公式の権限表で確認(要確認)
- [ ] **キーの秘密鍵(.p8)は、一度しかダウンロードできない**(公式)。ダウンロードして、すぐ安全な場所に移す
- [ ] 画面に表示される **Key ID** と **Issuer ID** を控える(公式の「Creating API keys for App Store Connect API」で確認)(要確認)

## 2. 鍵を安全に置く(リポジトリの外)
- [ ] `.p8` を、**アプリのリポジトリの外**に置く(例: `~/.appstoreconnect/AuthKey_XXXX.p8`)
- [ ] `chmod 600 ~/.appstoreconnect/AuthKey_XXXX.p8`
- [ ] **コミットしない・チャットに貼らない・ログに出さない**(`pre-commit` が `AuthKey_*` と `.p8` を止めるが、過信しない)
- [ ] 失くした・漏れた疑いがある時は、すぐ**失効**する(統合 → 編集 → キーを失効。失効は取り消せない)(公式)

## 3. 環境を整える
- [ ] 仮想環境(任意): `python3 -m venv .venv && source .venv/bin/activate`(`.venv` はコミットしない)
- [ ] `pip install pyjwt cryptography`
- [ ] 現在の端末だけに環境変数を設定する(`.zshrc` やリポジトリのファイルに**書かない**):
  ```bash
  export ASC_KEY_ID="(Key ID)"
  export ASC_ISSUER_ID="(Issuer ID)"
  export ASC_KEY_PATH="$HOME/.appstoreconnect/AuthKey_XXXX.p8"
  ```
- [ ] 履歴に鍵の値が残る入力は避ける(値をチャットや画面共有に出さない)

## 4. スクリプトの自己テスト(ネットワークなし)
- [ ] `cd appstore/automation && python3 -m unittest 2>&1 | tail -3` → `OK` と出る(偽の応答で動く)

## 5. 入力ファイルを作る
- [ ] AI が `appstore/kit.md` から `submission.json` を作る(`submission.example.json` が見本)
- [ ] **個人情報が入っていない**(姓名・メール・電話は対象外。入っていると止まる)
- [ ] 文字数の上限(名前30、サブタイトル30、キーワード100、プロモーション170、説明4000)を超えていない(超えると止まる)
- [ ] `bundleId` と `versionString` が、App Store Connect のものと一致している
- [ ] スクリーンショットを入れる場合: ファイルのパスは入力ファイルからの相対パス。**透過のない PNG / JPEG**。寸法は参照データと完全一致(`plan` が検査する)
- [ ] 価格を入れる場合: **新規の設定のみ**。既存の価格がある時は止まる(画面で変更)

## 6. `plan` を実行する(読み取りのみ)
```bash
python3 appstore/automation/asc_sync.py plan submission.json
```
- [ ] 何も書き込まれない(GET のみ)
- [ ] 出力の確認:
  - [ ] アプリ ID とバージョンの状態が、意図したもの
  - [ ] 各項目の「現在」と「新規」が、意図どおりの差分
  - [ ] `!` の注意(ロケールが無い、参照データを取得できない、既存のスクリーンショットがある、価格に二段階の承認が必要、など)を読んだ
  - [ ] 年齢制限を入れた場合: アプリの実際の内容と一致している(オーナーが確認)
- [ ] 差分をオーナーに見せる(AI は、ここで止まる)

## 7. うまくいかない時
| 症状 | 確認すること |
|---|---|
| トークンのエラー、HTTP 401 | Key ID・Issuer ID・`.p8` のパスが一致しているか。端末の時刻が正しいか(トークンの有効期間は20分以内) |
| HTTP 403 | キーのロール(アクセス)が足りない。権限の表で確認 |
| アプリが見つからない | Bundle ID が一致しているか。レコードを先に作ったか |
| バージョンが無い / 編集できない状態 | 画面でバージョンを作る。状態が審査中・公開中なら編集できない |
| 「ロケールが無い」の通知 | 画面で言語を追加してから、もう一度 `plan` |
| HTTP 429 | 回数が多い。少し待ってから再実行 |

## 8. `plan` の次(別の承認が必要)
- `apply` は、オーナーが差分を確認して**会話で明確に OK した後**にだけ。価格は `--confirm-price` で金額と地域を打ち直す。既存のスクリーンショットの置き換えは `--allow-delete-placements`。
- `apply` の後は、App Store Connect の画面で内容を確認する。**審査への提出は手動**。
- 手順の全体は `README.md`。
