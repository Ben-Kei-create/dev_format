# App Store Connect 申請キット作成指示書 v2.2
初回リリース・アップデート共通 / iOS・macOS対応 / 手動コピペ最適化

【最重要】これは AI 作業者に渡す共通指示書。依頼が「指示書のリライト」なら申請処理は実行せず編集のみ行う。

## 使い方と実行条件
1. `appstore/app_input.md` にアプリ固有情報(非個人情報)を入れる。
2. `review_prompts/` の段階1・2・3の審査チェックを全て完了させる。
3. **段階3まで全て通過してから**、この指示書で申請用のコピペリスト `appstore/kit.md` を作る。通過前に完成版を作らない。途中で求められたら、準備版と明記し、不足と完了条件を示す。
4. `kit.md` には個人情報を一切書かない(下記)。そのためコミットしてよい。
5. 個人情報の欄は、本人が App Store Connect で直接手入力する。

## 個人情報の扱い(最優先)
- **キットに書かない(本人が手入力)**: 姓名、メールアドレス、住所、審査用アカウントのパスワード、鍵・トークン、著作権表記に含まれる氏名。
- **電話番号**は、実番号を書かず `+81 XXXXXXXXXX` の形で書く。X の部分は本人が手入力する。
- 該当する欄は、【扱い】を「本人が手入力」とし、貼り付けブロックは作らない(電話番号だけ、上記の `+81 XXXXXXXXXX` を示す)。
- 著作権欄は、書式だけ示す(例: `© 年 氏名. All rights reserved.`)。氏名は本人が入れる。
- 個人情報をリポジトリ、コミット、PR、公開ページ、チャットに書かない。
- 個人情報以外(アプリ名、説明文、キーワード、公開URL、審査メモ、回答の選択)は、`kit.md` に実値で書いてよい。
- `scripts/pre-commit`(`setup.sh` が入れる)が、メールアドレスや電話番号らしい文字列、`private/` のファイルを含むコミットを自動で中止する。

## 入力欄の運用
1. AI は必ず `appstore/app_input.md` を最初に読み、過去のバージョンや他アプリの情報より、今回の明示値を優先する。コード・既存登録情報との矛盾は報告し、勝手に上書きしない。
2. 「自動確認」の欄は可能な限り AI が調べ、調べられない時だけ不足として報告する。未登録と不明を混同しない。
3. 初回は App ID・アプリレコード作成から案内し、更新は既存レコードを前提に変更点と必須の再申告だけを案内する。
4. 広告の設定やアプリ名を他プロジェクトへ引き継がない。広告ID(AdMob のアプリID・広告ユニットID)は App Store Connect の入力欄にないので、キットには含めない。
5. 完成キットは、App Store Connect を上から順に埋められるよう、画面名 → セクション → 項目名 → コピペ用の値／選択肢の順で出す。

## 自動入力(任意)
`kit.md` ができ、オーナーが望んだ場合は、`appstore/automation/` で、テキストのメタデータを API で入力できる(作る → `plan` → オーナーが OK → `apply`。審査への提出は手動)。個人情報の欄は対象外。手順は `appstore/automation/README.md`。

## 指示書の構成(必要な部分だけ読む)
この指示書は、トークンを節約するために分割してある。**常に読むのはこのファイル**。残りは、場面に応じて必要なものだけ読む。

| ファイル | 内容 | 読む場面 |
|---|---|---|
| `kit/01_principles_flow.md` | 目的と原則、申請モードの判定、対象アプリの特定、操作権限、作業フロー | キット作成の最初に必ず |
| `kit/02_output_format.md` | 出力形式(画面順 + 1フィールド1ブロック) | キットを書く時に必ず |
| `kit/03_first_release.md` | 初回専用: App ID・アプリレコードの登録順 | 初回リリースのみ |
| `kit/04_version_and_review.md` | バージョン情報、審査情報(審査メモ)、リリース方法 | 毎回 |
| `kit/05_app_info_privacy.md` | アプリ情報、プライバシー、アクセシビリティ | 毎回(更新時は変更がある時) |
| `kit/06_price_iap_regulation.md` | 価格、課金、規制・コンプライアンス、その他 | 該当する時 |
| `kit/07_quality_rules.md` | 記述・スクリーンショット・画像の品質ルール | 文面と画像を作る時 |
| `kit/08_web_sdk_xcode.md` | 公開ページ、AdMob・SDK監査、Xcode / Archive | 公開ページ・広告・ビルドを扱う時 |
| `kit/09_gate_summary.md` | 進捗の出力、完成の条件、終了時のまとめ、公式資料 | 完成を判定する時、まとめる時 |

- 審査メモの項目は `appstore/review_notes_template.md`、スクリーンショットは `appstore/screenshots.md`。
- 更新(アップデート)の時は、変更に関係する画面別のファイル(04〜06)だけ読む。
