# 申請キット指示書: 原則とフロー(§0〜5)

(入口: `appstore/submission_kit_instructions.md`)

## 0. 目的と運用原則
対象アプリの実装、Xcode設定、提出素材、Apple公式要件、公開ページ、App Store Connect で確認できる登録情報を調査し、ユーザー自身が管理画面を上から順に操作・コピペできる「申請キット」を作る。
対象は初回リリース、初回登録途中、既存バージョンのアップデート、メタデータ修正、iOS と macOS の両方。別アプリの情報を流用しない。
App Store Connect と Apple Developer の操作は本人が行う。AI は勝手にブラウザ操作、登録、提出、課金契約、公開を行わない。各画面の「入力値」「選択回答」「手動操作」「確認のみ」を厳密に区別する。
(例外: オーナーが実装完了を宣言し、API の実行を明示的に指示した場合に限り、`appstore/automation/` の承認の関所つきの API でテキスト・画像・年齢制限・価格の初回設定を入力できる。画面の自動操作はしない。審査への提出は常に手動。)
日付基準は作業時点の日本時間。Apple公式の最新の日本語画面表記を優先し、英語表示なら英語名を併記する。画面上にない欄を捏造しない。

## 1. 申請モードとビルド状態の判定
- A: 初回・App ID未登録
- B: 初回・App ID登録済み / アプリレコード未作成
- C: 初回・レコード作成済み / ビルド未アップロード
- D: 初回・ビルドアップロード済み / 審査準備中
- E: 既存アプリのアップデート
- F: メタデータ・プライバシー等のみの変更
- G: その他 / 判定不能(証拠と不足を示す)

判定根拠、対象プラットフォーム、App ID、Bundle ID、Apple ID、CFBundleShortVersionString、CFBundleVersion、アップロード済みビルドの有無、現ステータスを冒頭に記載する。最初の5行以内で、「今回必要なビルド形式」「現在ある/不足している」「初回/更新」を知らせる。申請に必要なのは Xcode プロジェクトそのものではなく、署名済みビルドであることを説明する。
更新時は既存設定を引き継ぎ、変更が必要な項目だけ再入力させる。登録済みの Bundle ID や SKU を変更できると誤案内しない。

## 2. 対象アプリの特定
- アプリ名、リポジトリとブランチ、Bundle ID、App ID、SKU、Apple ID(それぞれ確認状況を区別)
- 現行/申請バージョン、ビルド番号
- プラットフォーム、対応OS・端末・言語、カテゴリ、価格、配信地域、リリース方法
- 既存のレコード、過去の審査指摘、公開情報
- 広告・分析・課金・ログイン・外部通信・ユーザーデータ・権限
- 商標・素材・ライセンス・暗号化・トラッキング・子ども向け要件

アプリ固有の情報は他アプリから補完しない。提案は「提案」として、本人が確定した情報と区別する。
ソースがローカルに無い場合は、既存のチェックアウトを探し、なければ実在する URL で clone する手順を示す。URL 不明なら実行可能なコマンドとして出さない。

## 3. 共通オーナー情報
個人情報(姓名、メール、電話、著作権表記の氏名)は、キットに書かず、本人が手入力する。
サイト運営者、サイトのリポジトリ、問い合わせ先の表記などは、不明なら本人に確認する(推測しない)。
公開URLの規則は `web/common.md`。
管理画面の実情報や本人の新しい指示と食い違う場合は、勝手に確定せず差分を報告する。
- トレーダー(Trader)としての申告は、本人の方針を確認して従う。法的・地域別の必要情報は、実際の登録主体に基づき確認する。
- 配信方針は `app_input.md` に従う。国・地域別の法的要件、契約、年齢制限、輸出規制で調整が必要か確認する。
- 広告方針: 導入状況と種類は必ずコードと AdMob 設定で確認する。
- プライバシー方針: 初回は必要最低限。将来、興味関心データを扱うなら、機能導入・同意・開示の変更が必要。導入前に収集済みと申告しない。

## 4. 操作権限
- 承認なし: コード・SDK・権利・Apple公式仕様の調査、原稿作成、素材案とローカル画像生成、Web ページの作業ブランチ作成、ローカル検証、PR準備
- 明示承認が必要: アプリコード/Xcode設定/PrivacyInfo.xcprivacy の変更、権限・課金・広告・ATT の動作変更、管理画面での変更、ビルドアップロード、本番サイト公開、PRマージ、契約・税務・銀行口座の変更、審査送信、リリース
- 禁止: 依頼に含まれないアプリ削除、配信停止、アクセス権変更、秘密鍵・パスワード・トークンの出力

## 5. 作業フロー
1. モード・アプリ特定
2. App ID / アプリレコードの有無確認
3. コード・SDK・データ収集・権限・署名の調査
4. 公式仕様の照合
5. 説明文、申告回答、画像等の準備
6. 公開ページの準備
7. Xcode 検証・Archive・アップロードの要否確認
8. 入力キットの作成
9. 未完了・承認事項の明示
10. 本人による管理画面入力・審査送信

未完了項目があっても、貼れる確定済みの欄は先に出す。未確定欄は「入力保留」とし、理由と完了条件を示す。完成版と準備版を区別し、完成版と呼ぶのは必須要件が揃った時だけ。
